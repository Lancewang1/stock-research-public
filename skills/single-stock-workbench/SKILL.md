## 开始工作

1. 确认公司、研究截至时间、用户材料目录与输出位置；能从材料和当前请求确定的，不重复提问。首次使用先读 [研究方法](references/research-method.md)。
2. 盘点原始模型、模型日期、行情范围、研究摘录及原文是否齐全。保留原文件，记录来源位置、财务期间、币种、单位和口径。遇到凭据文件，不把凭据写入输出或浏览器代码。
3. 读取和核对材料，再提炼业务驱动及可编辑假设。区分公司历史实际值、券商预测、市场样本统计、研究推断和用户情景。已提供的模型与 API 清单不要求用户重复准备。
4. 按本次任务选择复盘或预测工作流；同时需要时，共用证据目录与业务驱动定义。缺失输入记录为缺口，不能以示例数或其他公司的数值补齐。
5. 用户给了既有看板时，以该看板的结构和交互为基线。本案例保留v9的价格图、三大复盘、估值子图、基准叠加、密集历史表及因子抽屉；增加内容时保持这些功能可用。UI美化优先级低于研究内容和模型。
6. 盈利预测页先展示完整可编辑盈利模型并默认展开，随后放Cloud Revenue驱动分析与折叠研究资料；Cloud快捷入口直接定位独立模型。用户2026-11-06要求暂时移除Capex分析展示，保留历史归档与引擎以便后续恢复。假设证据审计见[Cloud Revenue证据审计](references/cloud-revenue-evidence-audit.md)，明确无直接证据的成本率、训练占比和Google份额。分析模块内部按结论、量化结果、假设证据身份、可编辑假设、机构差异解释、折叠来源组织。删除没有功能的入口，不用证据数量替代分析框架；原始材料应能从相关结论或参数展开。

## 数据获取与跨公司研究

静态交付指浏览器不自动取数；制作时可使用用户已提供的API并把结果固定在本地。根据问题选择来源：EODHD/Wind核行情，SEC/公司IR核财报，Wind检索新闻和披露线索，FRED核宏观背景。先使用现有凭据，不要求用户重复提供；凭据仅保留在调用进程内，不进入HTML、案例JSON、日志、命令输出或打包文件。详见[取数与核验](references/source-workflow.md)。

分析Cloud或其他业务的需求时，追到客户、供应商、渠道和竞争对手的经营指标。阅读[跨公司证据到经营假设](references/cross-company-research.md)，区分需求、份额、交付、计费、收入确认和利润率；客户收入或供应商指引不能直接成为目标公司增速。

需要量化Cloud/Capex时，使用[独立模型方法](references/cloud-model-method.md)及`scripts/cloud-model.mjs`。客户覆盖Anthropic、OpenAI、其他AI客户，其他企业/GCP/Workspace为不重叠的残余服务；Google内部Gemini不计为外部客户收入。公开供应商关系不提供采购金额，缺少拆分时给出有标识、可修改且总额勾稽的研究假设，不能把估计拆分改标为历史实绩。

用户提供批量模型或研报ZIP时先盘点内部目录，去除重复文件与macOS资源叉，再按研究问题读取原件。文件名与内部公司、发布日期、财季标签可能不一致，以核实结果分别记录；公式和缓存值同时保留，不执行原模型宏。跨公司数据接入前核验Google分配、交付和确认的桥接变量，缺少时显示具体缺口。

本案例已有两批材料的盘点与实际使用范围，见[本地材料核对](references/local-material-review.md)。后续新增材料先比对该记录与来源哈希，避免重复提取旧版本。

## 基本面复盘

- 先明确时间窗口和价格口径。顶底是事后识别的观察点，不是证明当时能够交易的信号。
- 依次区分「起点当时已知」「期间新增信息」「终点之后的说明」。一份报告只有发布日期不晚于被分析时点，才能用于说明该时点的看法；只有日期没有发布时间时，不默认该内容在当天开盘前已知。
- 写清预期与实际之间的经营问题：收入由什么驱动，利润率如何变化，资本开支与现金回收是否匹配，监管变化可能影响哪个渠道或成本。每个解释给证据和可证伪问题，不凭价格下跌反推原因已经成立。
- 对卖方观点保留机构、发布日期、目标期间、财务与估值口径。后来报告不能倒填到历史顶底；没有原始预测及后续同口径实际值，不计算预测准确率。
- 每个事件连成「公开日期与盘前/盘后→新增信息→改变的预期→首个可观察交易日价格与相对表现→随后机构回应」。日期可定位主图，QQQ/XLC比较支持叙事但不替代叙事。没有匹配催化的跌幅如实保留，不能强行编成单因果解释。
- 最近回撤用`scripts/build_review_events.py`生成`assets/review-events.json`；发布前预期样本与次日媒体回溯分开，Search/Cloud等分部可比口径与总收入gross/ex-TAC、GAAP/调整EPS分别核实。
- 示例见 [GOOGL 2024 年中复盘](references/example-review.md)。其中研究观点来自旧包的二手摘录，示例没有宣称原文已经复核。

## 季度预测与预期差

- 盈利预测页顺序：第一部分为默认展开的完整盈利模型；第二部分为合同收入线和客户经济性线。两条线的关键证据默认可见，客户级参数可编辑；使用`assets/cloud-lines.js`维护双线界面。2026-11-06新增费用证据见[历史证据核验](references/customer-cost-historical-evidence-20261106.md)，不可将Wind转录费用直接当采购现金或Google份额。
- 当前客户默认`serviceMethod=contract`：仅对平均已验收容量计算保底及额外用量；最低计费比例初值0%表示情景暂不计保底，不表示已知合同没有承诺。保底包含对应使用量，额外用量需先扣除保底，避免重复；旧版取小值法保留可切换。客户训练预算独立输入，不因修改收入或推理费用率自动重设。

- 用用户模型识别业务结构、公式关系、历史数据与预测起点。先核对基准再开放假设编辑；不照抄模型中的输出充当计算。
- 自主Cloud和Capex预测先从历史实际、客户预算、份额、交付和成本生成；MS及其他卖方在算完后比较，不用卖方目标反向调出“独立预测”。对差异给出业务拆分、敏感性与单参数达标条件；多种独立反推解不能一起应用。
- 保留基准/较快兑现/较慢兑现及用户编辑情景，参数显示校准期、原始值、区间、来源身份和公式。客户收入、推理采购、训练预算分开；预算法和容量法交叉约束，不能相加。
- Capex按Google承担的资产新增与现金付款计算；价格或利用率降低不撤销既定容量投入，外售TPU和第三方客户自有设备不能直接计入Google固定资产。收入强度代理的部分明确标注为代理，不能冒充项目预算。
- 历史校准与预测力验证分开。领先指标检验按当时披露日期滚动留出，与简单历史基准比较；供应商收入相关不等于Google订单。若不能改善留出误差，不将其直接作为预测驱动。
- 提取或核对工作簿时读 [模型映射](references/model-mapping.md)，按其中的工作表、期间和单位定位数据。
- GOOGL 内置映射只用于匹配的原始工作簿。新增 GS、Barclays 等模型用于比较业务拆分、模型日期和口径；机构数量不构成真实性投票，较新的模型也不自动更正确。
- 收入、成本、费用、营业利润、非经营损益、税和稀释股数形成可解释的季度计算链。驱动变化后，由 `scripts/model.mjs` 计算情景结果，保持基准和用户情景可对比。
- 季度与年度必须可勾稽：已公布季度保留实际值，全年收入和利润按季度求和；年度 EPS 的分母按年度股数口径处理，不将季度 EPS 机械相加。年度股数假设与季度权重需要明确。
- 当前 GOOGL 季度样本为 2024Q1–2027Q4，实际值至 2026Q3 锁定，可编辑范围为 2026Q4 和 2027 年四个季度。2028 年保留年度情景编辑并从当前2027年度传导；季度数值为空，不生成2028季度明细。看板保留原包更长历史，来源和核验范围逐项区分。
- 内置情景以映射的 MS 季度同比增速为默认收入假设，并按同比基数递推。计算模型年度 EPS 使用季度普通股盈利分子汇总除以按各季度天数加权的股数，与 MS 原始年度 EPS 分开展示。
- 费用使用GAAP研发/销售/管理分项；SBC与折旧为已经包含在费用中的备查项，不能再次扣除。保留其他费用残差，不强行把未知费用塞进某个分项。
- 优先股股息和普通股盈利需要单列。2026Q3 SEC披露净利26,468百万美元、普通股摊薄分子26,170、股数12,368、EPS 2.12，原MS直接净利/股数得到约2.14；保留这一差异。可转优先股if-converted测试可能在季度与全年产生不同结果，当前年度情景EPS为季度普通股盈利汇总/加权股数，不冒充完整年度GAAP计算。
- 证据只支持方向时，显示「方向性证据」；用户或研究者输入的数值应标为情景假设。不能把新闻文本自动转成无说明的精确增速。
- 同口径同期间才计算差异。MS、GS、Barclays 的模型版本不同时，展示不同信息集的比较，不标成同一时点的市场共识。参见研究方法中的口径表和计算检查。

## 构建静态案例与看板

在 skill 目录运行，`<用户材料目录>` 指向含原 ZIP 和模型的目录：

```bash
python -X utf8 scripts/build_case.py --source-dir "<用户材料目录>" --output outputs/googl-case.json
python -X utf8 scripts/build_cloud_inputs.py --build
python -X utf8 scripts/build_review_events.py
python -X utf8 scripts/build_dashboard.py --case outputs/googl-case.json --output outputs/googl-dashboard.html
node tests/test_model.mjs outputs/googl-case.json
node tests/test_cloud_model.mjs
```

- `scripts/build_case.py` 提取材料并生成案例数据；`scripts/build_dashboard.py` 将案例与 `assets/dashboard.html` 组装成静态 HTML。
- 这两个入口兼容当前 Windows 工作区，使用现有 Python 环境即可。不要要求用户安装原 Demo 的 macOS 环境或手工运行其 shell 重建脚本。取数脚本依赖`requests`；离线重建不需要网络或API凭据。
- 没有原始模型、只需运行内置静态示例时，直接用 `python -X utf8 scripts/build_dashboard.py --case assets/example-googl-case.json --output outputs/googl-dashboard.html`。该样本是随技能附带的固定快照，不代表新取数；源文件齐全时优先重新提取。
- `scripts/model.mjs` 是浏览器与可运行检查共享的计算层。改动公式时同步验证收入加总、利润桥接、税和股数、季度年度关系及情景联动。
- `scripts/cloud-model.mjs`计算独立客户/供给和现金Capex情景；`assets/cloud-ui.js`展示可修改假设、机构对比和历史校准。把Cloud预测应用到盈利表时仅改未来季度，EPS按该表当前成本、税和股数计算；独立Capex不直接扣减利润。
- 输出是本地快照。写明每条序列真实截止日与生成日期；重建文件不等于获取新数据，未执行的 API 调用不得标为成功或实时更新。美债收益率、VIX、美元指数可能有不同截止日；不能把最后值前填成新的真实观测。
- 检查输出无占位预测、无非有限数值、无把缺失显示为零的情况。实际打开 HTML，核对中文、表格、数值编辑、复盘和来源说明；仅通过 JSON 解析不代表看板已验证。
- 当前用到的卖方模型和研究摘录保留原材料的内部使用范围，在产物中正常注明。不要把原模型或凭据嵌入可公开发布的示例。
