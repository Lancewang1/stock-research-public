# 先看公式，再修改底层假设

## 客户可以直接阅读的假设依据

根据 `Screenshot 2026-11-07 215915.png` 的反馈，首层说明直接回答“采用什么数值、来自谁、为什么采用”。例如搜索分销成本率应写“按照摩根士丹利2026年10月29日模型的搜索收入和分销成本测算，2027年一季度费率约为18.49%，我们据此作为预测起点”，并说明我们判断该费用随收入变化的经营逻辑。模型快照、冻结输入、覆盖规则与工作表地址不是客户叙述，放入默认折叠的模型取数明细。

摩根士丹利当前来源是2026年10月29日原始盈利预测工作簿；巴克莱当前来源是2026年7月24日模型。本地版链接到已存在的原始文件，便携版仅保留可展开的来源记录。未找到这两个版本的研报原文HTTP链接，不将模型称为PDF研报，也不以机构首页或2022年旧报告深链代替。公司披露等已有真实HTTP原文链接照常展示。原始工作簿不放入便携包。

我们自行推导的增长、成本分配或情景数值明确标为“我们的分析/研究假设”，首层说明具体判断，并通过“我们的分析”入口继续查看对应条目。已有用户自定义数值注明为用户情景，卖方或研究初值保留为参照。计算公式、编辑参数、期间和财务计算保持不变。

## 用户工作流

模型中的计算结果直接展示计算公式、所选期间的代入值和相关底层假设。用户可以从科目名称或具体数字进入；两种入口都应看见同一计算关系。结果本身不提供金额输入框，修改入口对应真正的驱动参数。

以 Search 收入为例：

`本期 Search 收入 = 上年同期 Search 收入 ×（1 + 本期同比增长率假设）`

上年同期收入作为公式基数展示；预测同比可以修改。同比增加 1 个百分点时，本期收入增加上年同期收入的 1%，并继续影响集团收入和盈利。历史收入保持只读，不能把修改结果金额再反推同比的旧流程作为默认编辑方式。

## 假设与分析的呈现

假设的简明依据默认可见，包括来源、参考信息和采用该数值的解释。公式中的底层假设也遵循这一要求。文件路径、内部参数名和代码位置可以辅助追溯，但不能替代用户可以直接读懂的叙述证据。

较长的分析、原文定位、来源细节和相关科目的详细内容继续折叠，点击后再展开。每次只显示当前项目；打开公式或编辑假设时保留所选期间与返回路径。

## 期间与分项

- 季度收入按上年同季与当前同比递推。2026/2027 年度汇总来自季度，不能在同一年度结果下再提供互相冲突的结果金额输入。
- 2028 是年度延展，使用上一年度收入与年度增长假设，不虚构 2028 季度数据。
- YouTube 订阅与其他订阅由订阅总额及份额假设拆分。调整份额在两项之间重新分配，合计只计入集团一次。
- 折旧由资产规模、资产倍率和使用年限计算；修改年限或资产倍率，不能直接修改折旧结果。冻结基准依赖仍只读。
- Cloud 计算项显示公式及其底层假设。编辑器沿用原有唯一控件，修改后先重算独立 Cloud 预览，显式应用后才写入主盈利模型。

Cloud 测算经应用或导入后，四项业务收入在主模型中属于外部情景输入，但仍不开放金额编辑。主模型展示只读来源并保留 Cloud 驱动入口；用户修改客户、价格或交付等假设后重新应用，避免主模型与下层测算分离。

默认派生的集团毛利率、研发费用率、标准化业务毛利率和初始 Cloud 成本倍率不能直接修改。已有保存或导入情景中的明确覆盖仍按真实假设识别，可以继续修改或恢复基准；不能把历史兼容要求变成新建结果覆盖的默认入口。显式 MS 反推按钮仍可写入一个条件解，写入后该值作为当前情景的输入管理。

主模型中的真实假设输入统一使用 `data-number-edit`，附带参数类型、参数名和期间；`data-assumption-rationale` 是默认显示的叙述依据。`data-model-formula-context` 标识当前公式，结果公式与代入值分别由 `data-number-formula`、`data-number-substitution` 标识。Cloud 继续移动同一 `data-cl-param` 控件至 `clNumberDrivers`，以 `data-cl-driver-input` 标识被公式使用的可编辑驱动。
