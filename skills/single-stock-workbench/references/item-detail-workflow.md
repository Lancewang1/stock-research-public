# 模型条目、证据与假设的逐层展开

2026-11-07最新要求：预测模型中每一个数字必须显示“假设”或“计算结果”；点击任意数字，弹框直接解释该数字的身份和来源，计算结果给出公式，假设给出来源、证据与分析。弹框每次只展示被点击的条目，不能把同主题的全部细分项一起显示。此规则优先于早期“点击数字先打开整组明细”的做法；完整模型和可改假设窗口继续保留。

2026-11-07 用户根据收入明细截图提出：完整模型保留，细节要跟随具体条目展开，不能在明细顶部放一排独立证据入口，再让用户到下方编辑表自行寻找对应关系。

## 用户路径

1. 首页仍是完整 40 行 MS 基准盈利模型，包含实际季度、预测季度与年度；预测数字旁直接显示身份，实际和缺失分别标识。
2. 点击数字，先显示该数字的期间、数值、单位、身份及直接来源。计算结果同时显示当前生效公式、代入值及可追溯依赖；假设显示来源、证据和分析，保留对应修改窗口。
3. 点击科目或数字来源中的分析入口，只进入该科目。收入的Search、Network、YouTube、订阅、Other Bets与Cloud通过下一级入口选择；选中某业务时不渲染其他兄弟业务的正文或编辑表。
4. 证据按当前条目的具体记录继续展开：摘要标题在前，展开后显示已有研究内容、来源身份、发布日期或定位信息，以及该证据能支持什么。没有可验证资料的项目直接说明缺口，不能拿其他科目的材料替代。
5. 公式依赖与进一步细分可继续点击，保留所选期间和返回上一级路径；不依赖整组标签切换寻找同一数字。
6. 客户修改假设后，相关结果、数字身份与完整模型重算；用户正在查看的条目保持打开。Cloud 详细收入测算继续采用显式“应用到盈利表”，不把预览自动写入主表。

## 数字身份与来源

身份来自当前计算路径，不来自控件类型。按同比递推的收入和按成本计算的毛利率即使有编辑窗口，未提交覆盖时仍是计算结果；编辑金额转换为同比输入时，金额仍须展示递推公式。直接写入的业务收入、税率、股数及其他情景参数属于假设。源模型的预测缓存作为本模型输入时标假设，并注明券商模型位置，不称为公司指引。

初始MS反推倍率注明固定条件、目标利润及实际反推公式，属于计算结果；应用或导入后保存为当前覆盖输入的数值，注明覆盖身份，不能推断用户输入方式。年度加总、加权股数、年度EPS和比率按各自公式解释；同一行季度输入、年度汇总及2028年度延展可能具有不同身份。原MS年度EPS与模型EPS分别保留来源。

来源必须直接指向当前数字：原模型工作表/单元格、冻结研究参数、用户当前覆盖或所用计算关系。不可只写“查看证据”或给出整组来源清单。显示金额、股数、比率和每股值时保持单位一致，金额输入的USD mn与表格的USD bn换算明确。基准比较注明初始基准，不能把当前覆盖的来源套到基准数字。

## 科目归属

- 收入证据归入具体业务；Cloud 的企业服务、AI 客户和独立 TPU 交付分别组织，客户合同容量与客户经济性都属于相应客户。
- 营业成本、毛利与毛利率显示各业务成本驱动及研究分摊说明；收入假设与成本假设不能混成一张无层级参数表。
- 研发、销售、管理及其他费用分别展示自己的计算关系和费用率覆盖；集团覆盖相对业务模型的影响仍可追溯。
- 折旧按服务器、其他资产、分配口径解释，保留年限与资产尺度编辑；摊销单列，不重复扣除已经计入成本费用的 D&A。
- 非经营收益、所得税、税率、股息、股数与 EPS 分别保留相关计算链和可编辑输入；派生结果不伪装成独立假设。
- SBC 与调整后利润保留限定调整口径；年度 EPS、MS 原始年度 EPS 对照与经营现金流备查继续说明其差异和联动范围。

## 数据与交互边界

本轮调整只组织既有模型、分析与证据，不刷新研究快照，不改变计算公式。MS 条件反推不是独立预测；非 Cloud 成本与利润的研究分摊不能改标为公司披露；客户采购份额、成本率和历史拆分仍保留假设身份。

已公布实际值保持锁定。2028 只有年度延展，不生成不存在的季度明细。情景保存、导入、导出、恢复以及 Cloud 应用入口保留；同一输入只保留一个编辑控件，避免多个副本相互覆盖。

折叠采用原生 `details` / `summary`，可通过键盘操作；嵌套证据默认收起。单项内容按精确科目、业务或客户过滤，不因它与当前条目属于同一主题就同时展示。模型抽屉支持返回上一级、关闭按钮、Escape 和遮罩返回主表。长历史、年度编辑和完整来源核验仍有专门入口。

这些是运行实际内联脚本的非视觉 DOM 检查，canvas 与布局由测试环境模拟，不是浏览器截图验收。
