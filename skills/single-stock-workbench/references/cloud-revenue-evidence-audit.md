# Cloud Revenue 假设证据审计

核对日期：2026-11-06；研究数据快照保持2026-11-05。本次追溯既有输入、构建代码及归档证据，不代表重新取得最新公司数据。

后续研究更新：2026-11-06另行完成研报库与在线检索，取得Wind转录的Anthropic总算力及功能分类费用表，并做了历史相容性和参数不可识别检查，见[客户成本历史证据](customer-cost-historical-evidence-20261106.md)。下表描述已部署参数的原始依据；新材料未写入生产参数，不将费用转录值直接当采购现金或Google份额。

## 客户预算：哪些有来源，哪些没有

| 参数 | 默认值或构建过程 | 实际依据 |
|---|---|---|
| Anthropic收入运行率起点 | 47bn × 1.5^(7/12) = 59.54bn；后续逐季+15% | 47bn来自归档2026-05-28融资公告的run-rate段；1.5倍年增长和15%环比由研究者设定，未经预测力检验 |
| OpenAI收入运行率起点 | 20bn × 2 = 40bn；后续逐季+15% | 20+bn来自2026-01-18 CFO文章的2025收入规模；以20为下界、翻倍及15%环比均为研究设定 |
| 推理采购成本率 | Anthropic 40%、OpenAI 45%、其他AI 40% | 当前已采用的材料没有支持这些具体比例的客户成本表或卖方估计；人为情景参数 |
| 训练预算 | 推理预算×训练占比/(1−训练占比)；占比60%/60%/45% | 假设比例推算，非独立训练预算；当前未取得客户财务或采购模型验证 |
| Google训练/推理份额 | Anthropic 30%/25%；OpenAI 6%/11%；其他AI 24%/30% | 人为情景参数，供应关系公告不提供采购分配 |
| 其他AI规模 | 从基期余额分摊及假设份额反算预算 | 残余校准，缺少独立客户清单和收入证据，不构成独立需求预测 |
| 净服务收入/GW | 2.7bn/90天×80%利用率×季度天数/90 | Barclays New Driver!EE117:EE118提供平均GW×季度有效收入的尺度；80%额外折扣不是原表披露利用率 |

来源绑定必须以具体字段为准：一个参数旁边列有公司公告，不意味着公告证明了整组数值。run-rate÷4是季度商业收入代理；商业收入也不是算力支出的硬预算上限，融资、现金储备及长期承诺均可能影响采购。

默认组合的算术含义：Anthropic总算力预算/季度收入代理=40%/(1−60%)=100%；OpenAI为45%/(1−60%)=112.5%。这两个比例是人为参数的结果，不是已经核验的实际财务比率，也不能因公式可计算而称为量化证据。

## 外售TPU：卖方原值与本模型调整

来源为用户提供的`GOOGL_BARC_analyst_model_20260724.xlsx`，发布日期由`ModelCover!F2`核对。结构化单元格记录保存在`assets/research-local-models.json`。

| 项目 | Barclays原模型 | 当前研究情景 |
|---|---|---|
| 2026Q4交付 | New Driver!EE130：0.90055GW | 0.5GW |
| 2026Q4单位收入 | EE131：14,285.714m/GW = 14.285714bn/GW | 14.285714bn/GW |
| 2027销售容量 | EK130 = SUM(EG130:EJ130)：3.7GW | 0.6+0.75+0.9+1.05 = 3.3GW |
| 2027单位收入 | EK131及逐季假设：18,309.524m/GW = 18.309524bn/GW | 14.5/15/15.5/16bn/GW |
| 2027收入 | EK127：67.745238bn | 0.6×14.5+0.75×15+0.9×15.5+1.05×16 = 50.70bn |
| 确认比例 | 原公式当季GW乘完整单价 | 引擎默认100%，未取得合同验证 |

3.3GW及逐季价格是参考卖方尺度后另外设置，未用订单、逐季验收或成交价校准。较低数值不能证明更准确。基期外售TPU约5.072bn还来自总Cloud超出成熟增长的部分×45%的研究分摊，45%没有单独披露依据。

原模型第127行标`External TPU Sales`，第131行标`TPUaaS Revenue per GW`。这支持“卖方使用GW×单位收入”的计算结构，但不能独立证明真实合同是一次性硬件转让。控制权转移、持续服务、支持和毛额/净额确认仍缺合同证据。不能把模型默认100%当作会计判断已完成。

## 上下游材料是否进入计算

| 公司/材料 | 实际使用位置 | 未实现的桥接 |
|---|---|---|
| Anthropic公告 | 收入规模起点、Google/Broadcom合作及2027起容量计划的时间参考 | 实际推理成本、训练预算、供应商份额、逐季验收均未披露 |
| OpenAI CFO文章及sub-processor名单 | 全公司收入/算力尺度及GCP基础设施供应关系 | 不识别Google金额、训练用途、GPU/TPU类型或份额 |
| Broadcom联合公告/2026Q3电话会Wind转录 | 供给与时间参考、联合容量防重复计数 | 芯片出货不能直接转成Google机房验收或Cloud收入；未形成数值映射 |
| Barclays/GS Broadcom 2026-06-04模型 | 行业AI收入、Custom Silicon/Networking结构比较 | Barclays Rev!A77:A90 Google旧拆分中v6单位最后非空CD80（Jan-2026）；后续缺失，未用于计算2026Q4或2027 Google采购量 |
| MS/GS NVIDIA 2026-08-27模型 | Data Center收入、GPU代际、ASP的供应侧研究资料 | 缺Google分配、芯片到GW及交付计费桥，未直接驱动当前Cloud公式 |
| NVDA/AVGO官方历史总收入 | 滚动留出领先指标检验 | 相同9季MAPE约5.26%，简单基准4.80%；未证明增量预测力，未套用回归系数 |
| Barclays Alphabet 2026-07-24模型 | 2.7bn/GW季度服务收入与外售量价的尺度参考 | 这是Google本身的卖方模型；不能称为上游独立验证 |
| MS/GS/JPM Google预测 | 输出对照 | 未用于生成客户预算；不同日期不代表同日共识 |

因此当前实现为公开规模约束下的可编辑收入情景，还未完成“上游出货→Google分配→验收容量→客户计费→Cloud收入”的完整供应链验证。
