# 研究证据、模型比较与计算方法

本文件约定如何把用户材料变成可追溯的研究判断和可计算情景。默认目标是验证研究逻辑与数字关系，不把任何一家券商模型当作答案。

## 证据记录

每条重要数字或结论尽量保留以下信息：原始文件或文档标识、页码或工作表／单元格／JSON 字段、发布日、获取日、财务期间、来源身份、币种和单位、原文是否可见、整理或推导过程。资料截至日、模型版本日和报告覆盖期分别记录。

| 证据层级 | 含义 | 使用方式 |
|---|---|---|
| 原始披露 | 公司公告、原始财报、可定位的业绩会原文、正式监管文件 | 支撑原始事实；仍核对期间、单位与修订情况 |
| 直接研究材料 | 可见的卖方报告、模型、会议纪要 | 支撑该来源在该日期的预测或判断；不能升级为公司事实 |
| 二手摘录 | 旧 Demo 中整理的观点、仅有标题和摘要的数据接口结果 | 可以提出待核的解释；显示原文缺失，不声称已独立验证 |
| 计算推导 | 由可定位输入计算的增速、估值、情景结果 | 公开输入与公式，区别于来源原话 |
| 用户／研究假设 | 为比较情景设置的增长率、利润率或其他参数 | 显示是谁设置、针对何期间、为何这样设；不标成市场共识 |

模型里标为实际值的数据仍是券商整理值；没有核对原始披露时，不能仅因历史期间已经结束就将证据级别改成公司原始披露。缺失单元格、缺缓存公式结果和真实的零值是不同状态。

## 不同模型的比较

先做口径对照，再比较数字。至少辨明：

| 维度 | 需要确认的问题 |
|---|---|
| 信息日期 | 文件名、模型内日期、财报实际截止期是否一致？日期来自哪里？ |
| 预测期间 | 日历年还是财年？季度与全年是否混用？该期在该模型中为实际还是预测？ |
| 单位与证券 | 美元百万、十亿还是每股值？股数单位是什么？GOOG／GOOGL 等证券口径是否一致？ |
| 收入 | gross revenue 还是 ex-TAC？业务段重分类及套保如何处理？ |
| 利润 | GAAP 还是调整后？股权激励、摊销、重组、投资收益是否剔除？ |
| 每股值 | 基本还是稀释股数？季度或全年加权平均？拆股前后？ |
| 现金流 | 经营现金流、资本开支、融资租赁和自由现金流的定义是否一致？ |
| 估值 | 现价或目标价对应日期、预测分母期间、净现金及非经营资产是否一致？ |

MS、GS、Barclays 的不同版本有不同信息集。差异可能来自预测、披露时点、重分类或会计调整，不能直接称为“谁对谁错”。文件名日期只能标为文件名日期，未经内页核对不得升级为确认的模型发布日期。

保持三层分离：来源模型原值；统一口径后的可比值与调整桥；研究者或用户的情景值。若无法可靠统一，则并列展示并解释不可比原因，不强行取平均或中位数。多家样本只有在期间、口径与日期范围清楚时才能称为“本样本统计”；不能自动代表全市场一致预期。

## 从证据到经营驱动

1. 找出真正改变盈利的业务变量。例如收入来自业务量、单价、份额或产能利用率；不要同时自由编辑相互推导的变量造成重复计数。
2. 明确证据支持的是方向、区间还是精确数值。管理层关于需求强弱的描述不等于具体增长率预测。
3. 将研究判断写成可以检验的命题：变量、期间、预期方向或区间、依赖条件、证伪条件和下一次验证材料。
4. 把数值假设接到公式，并记录哪些来自来源模型、哪些由研究者推导、哪些由用户输入。
5. 输出本期盈利影响和关键敏感项。只有模型实际实现了传导关系，才称为某变量的盈利或现金流敏感性。

资本开支不能直接当作当期损益费用。若模型只支持利润表，调整 capex 不应虚构即时 EPS 变化；只有建立折旧、资产投产及现金流关系后，才能展示相应传导。监管情景也需要先明确影响收入、分销成本、利润率还是估值，不能把一个标题直接换算为目标价。

## 季度盈利计算

采用模型可支持的最小完整计算链，明确口径。典型关系为：

```text
总收入 = 已映射业务收入之和 + 可识别的其他收入／套保／抵销
毛利 = 收入 - 营业成本
营业利润 = 毛利 - 经营费用
税前利润 = 营业利润 + 净非经营收益
净利润 = 税前利润 - 所得税 - 适用的非控股权益等调整
稀释 EPS = 归属于普通股股东的净利润 / 稀释加权平均股数
```

并非所有公司的成本和分部结构都适用上述展示方式。若输入使用比率，标明比率分母；若年度预测用季度展开，保留季节性来源，不无说明地四等分。单一有效税率是情景简化，亏损季度或一次性税项需要单独说明。

全年收入和利润是四个季度的合计；全年加权平均股数按相应口径计算，全年 EPS 由全年利润与全年股数计算。已公布季度加剩余预测季度形成全年预测，不能编辑未来假设后改写已公布历史。

基准数据与用户情景分别保存。改动某一输入后，所有依赖的输出重算；未关联的因子保持原值。按钮所称“恢复基准”应恢复明确标注的基准，不将用户修改静默覆盖进原始模型。

当前 GOOGL 案例提取的季度数值范围为 2024Q1–2027Q4，2026Q3 及以前为锁定实际值；可编辑 2026Q4 与 2027 年四季。2028 季度列只有标题且数值缺失，保留年度延展情景编辑并从当前2027年传导，不将年度数拆成未提供的季度情景。默认的业务收入同比增速来自已映射 MS 季度数据，情景递推使用对应上年同期的收入。

本案例的模型年度 EPS = 各季度普通股盈利分子合计 / 季度天数加权平均股数；实际季度优先读取披露的摊薄分子，预测季度以净利润减优先股股息。尚未实现完整全年if-converted转换/反稀释测试，该简化口径不自动等于公告或券商原始年度EPS，分开展示并解释差异。

### 一个可复查的情景操作

对 **2026Q4** 同时做两项改动：Google Cloud 收入同比增速比基准 **增加 5 个百分点**，公司毛利率比基准 **降低 1 个百分点**。这是用于展示模型联动的用户情景，既不是公司指引，也不是本例的研究结论。

核对如下可观察行为：2026Q4 的 Cloud 收入按 2025Q4 的基数和新增速计算；总收入、毛利、营业利润、税、净利润及 EPS 沿实际公式变化；2026Q3 以前的数值不变；2026 年合计反映 2026Q4 的变化。若后续季度仍以同比增速递推，2027Q4 的 Cloud 收入应使用变动后的 2026Q4 基数，避免把旧基数硬编码在情景中。

这两项冲击方向相反，净利润与 EPS 的合成方向应由公式计算，不能预先宣称一定上升或下降。预期差以同口径基准为参照，不能把演示情景改称目标价判断。

至少检查：

- 业务收入加总与总收入相符，抵销或残差有解释。
- 经营费用的符号、比率分母和股数单位一致，净利润与 EPS 能相互勾稽。
- 输入不改变时，情景输出复现该计算模型的基准；若不能复现券商原值，展示调整桥或未映射项，不隐藏残差。
- 季度合计与年度一致；股数变化时，年度 EPS 不依赖简单相加季度 EPS。
- 单因素变动的结果符合公式方向，零股数、缺失输入和非有限结果得到明确处理。
- 对比值所属的机构、期间、口径与版本日期始终可见。

## 历史复盘的时间纪律

为每个观察点分别设定信息截止时点。财报期末不等于公告日；公告日不等于开盘前已知。历史估值应使用当时可用的财务分母，不能固定给季末加若干天后就宣称是真实披露时点。

把复盘组织为三个部分：

1. **起点当时已知。** 记录价格、已公开经营数据和在该时点之前发布的观点。没有当时材料，就明确该部分尚不能重建。
2. **期间新增信息。** 按实际发布日期记录财报、指引、行业和监管变化；区分观察事实与候选解释。
3. **终点之后的说明。** 后续报告、后来发生的结果及今日回看都放在这里，只用于检验或补充，不能回填为终点前的市场观点。

复盘主线回答“经营预期的哪一环可能变化、现有证据能支持到哪里、还缺什么才能证伪”。价格收益是观察结果，不是各事件贡献的因果分解。没有可靠因子模型和对应数据，不把跌幅分成精确的财报、监管、情绪贡献百分比。

比较历史预测与实际，需要原预测发布日期、预测期间、同口径预测数、之后的实际披露和核对方法。目标价调整及股价涨跌本身不提供盈利预测准确率，也不证明机构当时判断正确。

## 交付与未完成项

静态 HTML 展示其生成时写入的数据，不自动联网。用户本地改情景不代表卖方模型已更新；只有实现并验证保存功能时才宣称改动能跨会话保存。

把缺口写具体，例如“缺 2024-07-10 前的原始报告，无法还原起点预期”，而非笼统写“数据不足”。已有材料足够的部分继续完成。新增公司先验证映射、公式和案例，验证范围之外不宣称可通用。

卖方授权模型和内部研究摘录保留原有使用范围；只在产物中注明必要的内部资料标识，不增加与本地研究任务无关的审批步骤。
