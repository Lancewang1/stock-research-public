# 独立Cloud与现金资本开支情景

`scripts/cloud-model.mjs` 从已披露历史、可编辑客户情景和资产假设计算2026Q4至2027Q4。MS及其他券商只在计算结束后作为对照，不进入独立预测，也不用于把默认参数调到券商答案。全部金额为十亿美元（USD bn），容量为GW，比率存小数；与原利润表模型的百万美元数据连接时乘1,000。

## 历史锚点与估计拆分

`assets/cloud-inputs.json` 保留官方Cloud总收入和集团现金资本开支的季度历史、发布时间及来源。最后历史季度是基期；预测期必须紧接历史、连续且不覆盖实际期。任何历史、基期、券商对照修改路径均被计算引擎拒绝。

Google没有公开本模型需要的完整客户收入、已验收容量、硬件销售及企业服务拆分。数据文件的基期客户与外售TPU值是**研究估计**；企业/GCP/Workspace残余服务等于已披露Cloud总额减这些估计。基期拆分严格勾稽总额并锁定，不把估计标作公司实绩。客户预算、Google份额、容量、满载净价、自有资产比例和设备/设施成本的未来值可以修改；参数元数据须显示其依据和估计身份。

## 服务收入

其他企业服务含Workspace、普通企业GCP及未单列业务，排除单列客户服务和外售TPU。季度递推为：

```text
企业残余服务本季 = 上季企业残余服务 × (1 + 历史季节性环比 + 情景增速调整)
推理采购预算 = 本季平均年化商业收入运行率情景 / 4 × 推理成本率
训练采购预算 = 本季独立训练预算情景
客户季度算力预算 = 推理采购预算 + 训练采购预算
训练需求金额 = 训练采购预算 × Google训练采购份额
推理需求金额 = 推理采购预算 × Google推理采购份额
Google服务需求金额 = 训练需求金额 + 推理需求金额
容量可支持收入 = 平均已验收可计费GW × 利用率 × 满载净价 × 本季天数/90
客户服务收入 = min(Google服务需求金额, 容量可支持收入)
```

客户分Anthropic、OpenAI和其他AI客户。`budgetMethod='revenueAndTraining'`把收入运行率情景、推理成本率及独立训练预算直接接入计算，三个输入均可编辑；总预算与训练比例变为派生只读。公开ARR/run-rate只提供规模锚，年化运行率除四是本季商业收入的情景代理，不是公司季度确认收入。不同公司的收入口径、免费用户推理成本及研发训练费用也未必一致，需要保留定义差异。

兼容的`budgetMethod='direct'`则直接使用季度总预算和训练比例；它不同时追加收入运行率法的预算。两种预算方法都表示客户全部平台的算力支出情景，乘Google份额后才形成对Google的服务需求；若以后输入Google专属采购合同，必须改用合同履约桥，不能再次乘份额。预算已含训练及推理两部分，不能把它们再与总预算相加。

2026-11-06起默认方法为`contract`，上面的取小值公式作为旧版`constrainedBudget`对照保留。设满额容量计费C=平均验收GW×净价×天数/90，最低计费比例f、利用率u，Google预算需求D：保底=C×f；额外用量=min(max(D−C×f,0),C×(1−f)×u)；服务收入=保底+额外用量。最低计费比例初始0%，只表示本情景不计保底，不证明真实合同不存在承诺。零保底时与旧版相同；未验收容量不产生保底。预算低于保底时显示覆盖不足，不自动削减保底。此为简化合同情景，未实现取消、违约、独立价格的预留与超额计费等条款。

界面保留`constrainedBudget`、`budget`与`capacity`对照方法；两条线结果不相加。预算法不能因此被说成已经验收；容量法不能因此被说成客户已同意足额付款。训练/推理确认收入按对应需求金额比例分配，是情景分配规则，不是取得了独立客户会计记录。客户经济性中的算力超收入缺口不含其他费用、融资或现金余额，不是实际现金消耗。

净价定义为**90天、100%利用率的情景净收入/GW**。Barclays模型中的每GW季度收入只提供尺度参考，原模型没有披露利用率，不能声称该数是公司满载报价。假设单独修改时，服务需求、产能约束和最终收入同时展示；有效Google份额与利用率最高为100%，倍率超过边界会显示封顶提示。

## 外售TPU与去重

```text
外售TPU本季收入 = 本季控制权可转移的交付GW × 净售价/GW × 本季确认比例
Cloud总收入 = 企业残余服务 + 三类客户服务 + 外售TPU收入
```

该简化公式只适用于所输入批次中符合控制权转移条件的硬件/软件金额；安装、支持、延保、退货权和回购保证需要进一步分拆。模型没有自动把联合5GW协议变成当期交付，也没有把多年最低采购额均摊到各季。

每份合同和每批设备只分配一次。Google/Broadcom联合容量、Broadcom设备融资/租赁、Google硬件销售、Google云服务及股权投资是不同口径。外售TPU收入只代表Google销售部分，不能再把Broadcom上游销售或客户租金加进Cloud。历史MS基准是否已含订单只在对照或应用差额时检查，不能把独立预测再加到原Cloud收入上。

## 自有资产与现金资本开支

AI客户资本投入由**自有计划/已交付容量增量**驱动，不由客户当期已实现服务收入驱动。因此，在容量路径不变时，下调客户预算、利用率或服务净价，不会把已经部署的资产投资抹去。

```text
自有客户容量 = Σ(客户平均验收GW × Google自有资产比例)
已有客户资产容量 = max(锁定基期容量, 之前各季自有客户容量)
新增自有客户容量 = max(本季自有客户容量 − 已有客户资产容量, 0)
AI设备扩容 = 新增自有客户容量 × 设备成本/GW
AI设施扩容 = 新增自有客户容量 × 设施成本/GW

自有企业残余服务增量 = max(本季企业残余服务×自有比例 − 上季对应金额, 0)
企业设备扩容代理 = 自有企业残余服务增量 × 企业设备资本强度
企业设施扩容代理 = 自有企业残余服务增量 × 企业设施资本强度

基期Cloud资本开支估计 = 基期集团现金资本开支 × (1 − 非Cloud分摊比例)
维持投入 = 基期Cloud资本开支估计 × 维持比例
设备付款计划 = (维持投入×设备比例 + 企业设备扩容代理 + AI设备扩容) × 设备成本倍率
设施付款计划 = (维持投入×设施比例 + 企业设施扩容代理 + AI设施扩容) × 设施成本倍率
集团现金资本开支 = 当季设备现金付款 + 当季设施现金付款 + 非Cloud资本开支情景
```

基期客户容量由数据层的固定拆分及参考净价一次估计，运行时不随用户调整净价或利用率而倒改。没有设备报废表时保留历史容量最高值，容量下调后反弹不会把闲置自有设备重复购入；维持投入另行保留。Google自有资产比例排除第三方持有的设备和设施；外售TPU库存也不计入Google固定资产资本开支。服务容量是平均验收容量的代理，并非逐项目期末投产台账；使用统一每GW成本忽略芯片代际、训练/推理配置和设备转用差异，因此这是可检查的简化资产情景，不是施工或采购预算。

默认设备和设施付款与该季度部署假设同期，代表当季现金付款简化。可以分别设置0–4季付款滞后，形成收货后付款情景；这不是建设提前期。预测开始前缺少详细付款表的滞后部分，按锁定基期现金资本开支的设备/设施比例估计，并显示提示。资本化时点、建设期预付款、融资租赁本金及供应商应付变动尚未形成完整现金流表。

非Cloud分摊、维持比例、设备比例和每GW成本均不是公司公开分部成本。企业资本强度基于集团历史资本开支与Cloud增量校准，再分配企业部分，属于代理关系；Search/Gemini等自用AI扩张是集团资本开支情景的重要独立缺口。未来非Cloud支出可通过倍率和环比调整，不能声称Cloud足以解释全部集团资本开支。

资本开支不直接扣当期EPS。本引擎没有完整固定资产、折旧、融资租赁及税表；联动原利润表时只传递独立Cloud收入，额外利润率/边际成本情景必须明确显示，不能把资本开支当经营费用。

## 年度、敏感性与机构对照

全年Cloud和现金资本开支按四个季度加总。2026年使用已披露前三季度加2026Q4情景；2027年使用四季情景。缺季不输出完整全年数，缺失实际资本开支不当零。混合实际与预测年度不伪造全年客户拆分，只展示预测部分的拆分覆盖范围。

`runCloudSensitivity` 固定其他参数，对十个全局驱动分别做局部冲击：环比调整±1个百分点，其他倍率±0.1或当前值10%。约束存在时，预算或容量的局部敏感性可以为零；这不表示该因素在更大范围内不重要。情景差异按企业、三个客户、外售TPU逐项勾稽。

MS反推只回答“其他参数不变，单独改这一参数，能否达到该季MS Cloud收入”。引擎在明确范围内求解预算、容量、Google份额、外售TPU量或企业增速调整。无法达到时返回`out_of_range`和上下界结果，不填虚构答案；五种解是互斥的单参数实验，不能同时应用，也不能推断机构采用了这些假设。机构模型的日期、来源和口径差异始终保留。

现金资本开支另做设备成本、设施成本、非Cloud支出及容量倍率的单参数反推，并同时返回相应Cloud收入。它与Cloud收入反推是两组独立实验，不会自动构成同时满足两个机构目标的解。

`data.backtest` 是数据构建器产出的总量滚动留出检验，按预测起点限制披露时间。它检查历史Cloud和现金资本开支的简化统计基准，不验证没有历史实绩的客户拆分、5GW兑现、外售TPU参数或新增资产模型。较低误差不使研究假设变成事实，也不表示投资回报已经回测。

## 接口与验证

```js
calculateCloudCase(data, { 'global.customerBudgetMultiplier': 1.2 })
calculateCloudCase(data, { 'customers.Anthropic.commercialRevenueRunRateBn.0': 60 })
resetCloudOverrides() // {}
cloudPresets(data)
runCloudSensitivity(data, overrides)
requiredMSParameters(data, overrides)
```

覆盖支持明确许可的扁平点路径，亦支持等价嵌套对象；数组索引必须落在五个预测季度内。未知路径、实际历史、基期、机构原值、缺失/非有限输入和越界比例会报错。计算不改输入对象。基准、偏弱和偏强预设都是研究情景，重置恢复数据文件的研究基准。

运行 `node tests/test_cloud_model.mjs assets/cloud-inputs.json` 核对独立算术、训练/推理分配、预算与容量约束、固定容量下需求冲击不抹去资产投入、第三方与外售TPU排除、现金付款滞后、历史锁定、全年勾稽、敏感性和单参数机构目标反推。
